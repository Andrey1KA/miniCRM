# Решения и допущения

Задание в этих местах можно понять по-разному. Ниже то, как сделано в этой версии.

- Автором задачи становится постановщик, который её создал. Дату создания ставит база. Подставить чужого автора или другую дату запросом нельзя.
- Постановщик может править и удалять стройку и задачу в любом статусе, включая «Принята».
- Удаление задачи снимает её историю. Удаление стройки снимает её задачи и их историю. Отдельным запросом историю добавить, изменить или удалить нельзя.
- Исполнителя можно сменить в любом статусе. После смены прежний исполнитель задачу больше не видит. Если это была его единственная задача на стройке, стройка тоже пропадает из его списка.
- Задачу можно перенести на другую стройку. На новой стройке она видна её исполнителю.
- На карточке стройки исполнитель видит только свои задачи. Чужие строки база ему не отдаёт, поэтому общий список на этой карточке собрать нельзя.
- Принять задачу или вернуть её на доработку может любой постановщик, не только автор.
- Смена статуса идёт одной функцией базы. Прямая правка строки задачи исполнителю недоступна: такой запрос не меняет ни одной строки.
- История пишется сама при создании задачи и при каждой смене статуса. В ленте создания исходный статус пустой, новый — «Новая».
- Роль задаётся при создании учётной записи и вошедший пользователь её не меняет. Открытая регистрация выключена в настройках Supabase. Дополнительно база не создаёт человека, если при создании не указана роль постановщика или исполнителя. Демо-пользователи появляются из `supabase/seed.sql`.
- Время в интерфейсе показывается по Москве.

## Что не доделано

- Приложение ещё не выложено на постоянный адрес.
- `supabase/tests/access_checks.sql` на живой базе не запускался. Сценарии видимости проверены через интерфейс тремя демо-пользователями.
- Если задачу примет второй постановщик, который её не создавал, исполнитель может увидеть в истории подпись «Сотрудник» вместо имени. В демо постановщик один, и имена отображаются.
